# Shopify product picker and explicit draft creation

## Intent and approved direction
Make the Shopify association understandable and usable on a phone, and let an unbound bulk lot deliberately create a Shopify product when no appropriate existing product is available. Julien approved planning and execution with Luna agents. Keep two independently reviewable feature commits: picker, then draft creation. Work on main; verify before pushing.

## Ownership
Existing linked products remain Shopify-owned. Newly created products also receive a linked mapping: creation seeds stock once, subsequent reconciliation must never overwrite their stock, title, SKU, price, or publication. Existing managed mappings and their publish switch keep their current behavior. Creating is an explicit external mutation, never an automatic consequence of empty search results. No change to purchase history, imported sale deduplication, or stock observation.

## Picker
Replace the long inline explanation and autocomplete popover with a compact Shopify product section and a Link existing product button. A dedicated AppDialogShell opens full-screen at the existing mobile breakpoint and as a normal dialog on desktop. Put the search field at the top; do not autofocus it. Render results in the scrollable body with wrapping product title, separate variant, SKU and price; no single-line concatenation/truncation. Keep the existing 300ms debounce, minimum two characters, eligibility diagnostics, paging, errors and request ownership guards. Select the variant and an active location; automatically select the sole location. A sticky Use product action returns to Edit inventory. Parent Save remains the only action that persists an existing-product link. Cancel/close must not silently commit a picker draft. Keep the selected summary visible and editable before saving.

## Creation flow
For a connected, unbound bulk lot, show Create Shopify product separately from search. Disable creation while name/SKU edits are unsaved; explain that saved inventory details are used. A dedicated preview dialog reads authoritative server data and active shop locations. Show title, Sealed box variant, SKU, price with explicit currency, and initial sealed-box quantity. The user chooses a location and presses Create draft and link. Show a brief statement that the product stays a draft until published in Shopify, and Shopify owns future stock and product management. Do not publish, activate, or mutate any other product. On success, show binding details immediately in Edit inventory; closing the parent afterward does not undo this explicit action.

## Backend interfaces and validation
POST /integrations/shopify/products/create-preview accepts {workspaceId?, lotId}, requires scope owner, and returns {preview:{title,variantTitle,sku,price,currency,quantity,locations:[{id,name}],previewToken}}. The preview token is a deterministic SHA-256 fingerprint of the authoritative creation data (including shop/generation and active locations), not permission or a client-provided quantity.
POST /integrations/shopify/products/create accepts {workspaceId?,lotId,locationId,previewToken} and returns {listing}. Derive title/SKU/price/currency/quantity from the saved scoped lot, authoritative live pricing when entity-backed, and authoritative sales; never trust browser-provided product fields or stock. Validate positive price, safe nonnegative sealed stock, bulk lot, matching selling/store currency, valid active location, and current connection. Recompute the preview fingerprint and reject stale previews before mutation. Imported sales are counted once through their authoritative sale records. Reuse existing order-webhook setup.

## Retry and identity
Serialize create with the existing scope key 0 and lot leases, the same ordering as linking. Use a deterministic scope+lot handle distinct from managed products, plus an ownership metafield containing its stable hash. Before creating, look up that exact handle; recover only if the ownership marker, sole tracked sealed-box variant, and requested location are valid. Never update a recovered product or re-seed its stock. New product creation is one synchronous productSet that includes DRAFT, tracking, price and initial inventory at the chosen location. On an ambiguous provider error, look up the handle again to recover a completed creation; otherwise surface a retryable error. Persist a linked mapping with creation handle so a repeated successful request returns its mapping without Shopify mutations. An unrelated existing mapping or handle collision is a conflict. Lease and connection-generation guards run immediately before mutation and persistence. No blind retry of productSet within a request.

## Limitations
A draft created remotely before a failed mapping write may remain in Shopify; retry recovers it by deterministic identity. Shopify data can change while previews are open, so stale previews must be refreshed. No image upload, variant customization, catalog import, relinking, or publication action in this change. Test the provider boundary with request/response contracts; no live merchant mutations without credentials.

API tests cover owner/scope boundaries, draft status, initial quantity after box/pack sales, currency mismatch, stale preview, invalid location, ownership collision, retry after ambiguous creation/mapping failure, duplicate submission, and no subsequent linked reconciliation mutation.
