# Dependency advisory review — 2026-10-18

The review used fresh `npm audit --json` results for the root, API, and realtime lockfiles. Audit totals include development dependencies. The “omit-dev JSON” column records the raw result of `npm audit --omit=dev --json`; treat it as npm's omitted-development audit view, not as a count of packages shipped in the application bundle.

| API | 12 (1 / 1 / 8 / 2) | 0 | 0 | 0 |

Before the updates, confirmed root production dependency paths included direct `@capacitor/android` (critical), direct `vue` and its `@vue/server-renderer` (high), plus production dependency-graph paths through Vue's compiler dependencies and Vuetify's optional tooling peers. In the base lock, production `vuetify` peers `vite-plugin-vuetify`; that plugin peers Vite, and both plugin and Vite are marked `devOptional`. The captured `--omit=dev` audit JSON reported eight vulnerable package records (including Vite, esbuild, PostCSS, nanoid, and source-map-js); this is the raw npm result, not proof that all eight are bundled into shipped client code. A read-only `npm ls ... --omit=dev --all` graph showed the peer/compiler paths remain represented in npm's omit-dev view. The full root audit also contained vulnerable transitives across Babel, Rollup, Workbox, XML parsing, URL handling, browser mapping, brace expansion, and Undici. API's 12 findings were development/test-tool paths: direct Vitest plus transitive `@vitest/mocker`, `tinypool`, Vite, Rollup, PostCSS, minimatch, picomatch, nanoid, brace-expansion, source-map-js, and esbuild. Realtime's sole finding was direct production `ws`.

Compatible updates brought Capacitor Android/Core to 8.5.3, Vue to 3.5.44, and realtime's lock-resolved `ws` to 8.22.0. Root and API now use Vitest 4.1.12 and `@vitest/coverage-v8` 4.1.12; the API declares the coverage provider directly so its standalone install can run coverage. Lockfiles also contain the safe compatible transitive updates selected by non-force `npm audit fix`. No vulnerable records remain in the final full audits or the final raw `--omit=dev` audit JSON.

Vitest 4 compatibility review found a non-component unit-test hook returning `apiCall.mockReset()`. The runner treated the returned mock function as a cleanup callback and invoked it without the API arguments; wrapping the reset in a block makes the hook return `void`. Standard root tests then passed. Vitest's V8 coverage remapping changed in v4, so coverage percentages can differ from the prior runner even when the included files are unchanged.

The published advisory records identify the patched Vitest mocker release as 4.1.11 and the Tinypool patch as 2.1.2. The project uses Vitest 4.1.12, which also removes Tinypool from the test-runner dependency tree.
